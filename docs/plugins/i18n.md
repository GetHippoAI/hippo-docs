# Internationalization (i18n)

Hippo supports 10 languages. Proper internationalization ensures your plugin works well for users worldwide.

## Supported Languages

| Code | Language | Region |
|------|----------|--------|
| `tr` | Turkish | Turkey |
| `en` | English | International |
| `de` | German | Germany, Austria, Switzerland |
| `fr` | French | France, Belgium, Canada |
| `es` | Spanish | Spain, Latin America |
| `pt` | Portuguese | Portugal, Brazil |
| `it` | Italian | Italy |
| `nl` | Dutch | Netherlands, Belgium |
| `ru` | Russian | Russia |
| `ar` | Arabic | Middle East, North Africa |

## Directory Structure

The scaffolding tool creates a `locales/` directory with JSON files for each language:

```
locales/
├── tr.json
├── en.json
├── de.json
├── fr.json
├── es.json
├── pt.json
├── it.json
├── nl.json
├── ru.json
└── ar.json
```

## Locale File Format

Each locale file contains translations for your plugin:

```json
{
  "name": "Weather",
  "description": "Get current weather and forecasts for any location",
  "tools": {
    "get_weather": {
      "description": "Get current weather conditions for a city"
    },
    "get_forecast": {
      "description": "Get weather forecast for the next several days"
    }
  },
  "messages": {
    "city_not_found": "City not found. Please check the spelling.",
    "api_error": "Failed to fetch weather data. Please try again.",
    "forecast_success": "{days}-day forecast for {city}"
  }
}
```

## Required Fields

At minimum, you must translate:

| Field | Description |
|-------|-------------|
| `name` | Plugin name displayed in marketplace |
| `description` | Plugin description in marketplace |

## Optional Fields

You can also translate:

| Field | Description |
|-------|-------------|
| `tools.[name].description` | Tool descriptions (helps AI in user's language) |
| `messages.*` | User-facing messages returned by handlers |
| `errors.*` | Error messages |
| `config.*` | Configuration field labels and descriptions |

## Using Translations in Handlers

Load and use translations based on the user's locale:

```typescript
import * as fs from 'fs';
import * as path from 'path';

// Cache loaded translations
const translations: Record<string, Record<string, any>> = {};

function loadTranslations(locale: string): Record<string, any> {
  if (translations[locale]) {
    return translations[locale];
  }

  const filePath = path.join(__dirname, '..', 'locales', `${locale}.json`);
  try {
    const content = fs.readFileSync(filePath, 'utf-8');
    translations[locale] = JSON.parse(content);
  } catch {
    // Fallback to English
    const fallbackPath = path.join(__dirname, '..', 'locales', 'en.json');
    translations[locale] = JSON.parse(fs.readFileSync(fallbackPath, 'utf-8'));
  }

  return translations[locale];
}

function t(locale: string, key: string, params?: Record<string, string>): string {
  const trans = loadTranslations(locale);
  const keys = key.split('.');
  let value: any = trans;

  for (const k of keys) {
    value = value?.[k];
    if (!value) return key; // Return key if translation missing
  }

  if (typeof value !== 'string') return key;

  // Replace {param} placeholders
  if (params) {
    for (const [k, v] of Object.entries(params)) {
      value = value.replace(`{${k}}`, v);
    }
  }

  return value;
}

// Usage in handler
export async function handle_track_price(
  params: Record<string, unknown>,
  ctx: PluginContext,
): Promise<HandlerResult> {
  const url = params.url as string;

  if (!isValidUrl(url)) {
    return {
      success: false,
      error: t(ctx.locale, 'errors.invalid_url'),
    };
  }

  // ... tracking logic ...

  return {
    success: true,
    message: t(ctx.locale, 'messages.tracking_started', { product: productName }),
  };
}
```

## How Translations Are Used

### In the Marketplace

The Hippo marketplace displays plugin `name` and `description` in the user's language.

### In AI Responses

When the AI uses your tool, it reads the tool descriptions in the user's language to better understand context.

### In Handler Responses

The `message` and `error` fields in `HandlerResult` are shown to users, so they should be in the user's language.

## Best Practices

### 1. Start with English

Always complete `en.json` first as it serves as the fallback.

### 2. Use Placeholders for Dynamic Content

```json
{
  "messages": {
    "found_items": "Found {count} items in {category}"
  }
}
```

### 3. Keep Messages Short

The AI summarizes responses, so keep messages concise:

```json
{
  "messages": {
    "good": "Event created for tomorrow at 3 PM",
    "bad": "I have successfully created a new calendar event scheduled for tomorrow afternoon at 3:00 PM local time"
  }
}
```

### 4. Test with RTL Languages

Arabic is a right-to-left language. If you use any formatting, test that it displays correctly.

### 5. Avoid Hardcoded Strings

Never hardcode user-facing text in handlers:

```typescript
// Bad
return { success: false, error: 'City not found' };

// Good
return { success: false, error: t(ctx.locale, 'errors.city_not_found') };
```

## Integration with manifest.ts

You can also include translations directly in the manifest for simple plugins:

```typescript
export const manifest = {
  slug: 'weather',
  name: 'Weather',
  description: 'Get weather forecasts',
  // ...

  i18n: {
    en: {
      name: 'Weather',
      description: 'Get current weather and forecasts for any location',
    },
    tr: {
      name: 'Hava Durumu',
      description: 'Herhangi bir konum icin guncel hava durumu ve tahminleri al',
    },
    de: {
      name: 'Wetter',
      description: 'Aktuelles Wetter und Vorhersagen fur jeden Standort',
    },
    // ... other languages
  },
};
```

This is loaded into the database when the plugin is registered and used by the marketplace UI.
